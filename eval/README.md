# 中文记忆评测集

84 个用例，按 Agent 实际看到的效果打分：回放多天对话后，**该记的记住了没有、不该记的有没有记、
查的时候能不能查到对的、会不会查到已经过时的**。

纯标准库，纯规则路径（运行时会去掉 `OPENAI_API_KEY`），结果可复现，一次约 15 秒。

```bash
python3 eval/run_eval.py                    # pending 模式：add-pending，每天结束 consolidate
python3 eval/run_eval.py --mode capture     # capture 模式：每句话都 capture（模拟 Agent 主动写入）
python3 eval/run_eval.py -v                 # 列出每条失败断言和当时的活跃记忆
python3 eval/run_eval.py --only correction  # 只跑某一类
python3 eval/run_eval.py --json out.json    # 保存逐条结果，便于前后对比
```

## 用例类别

| 文件 | 数量 | 测什么 |
|------|------|--------|
| `basic.json` | 12 | 身份、健康、偏好、关系等基础事实能否写入并查到 |
| `noise.json` | 11 | 寒暄、计算、翻译、提问等不该入库 |
| `privacy.json` | 3 | 密码、API Key、身份证号不该入库 |
| `correction.json` | 13 | 带更正词的修正（说错了 / 其实是 / 不再 / 换成 / 逗你的……），查询时不应再看到旧说法 |
| `preference_shift.json` | 5 | 没有更正词的隐式变化（改喝美式、分手、换手机） |
| `no_conflict.json` | 8 | **对照组**：相似但不冲突的事实不能被误合并或误失效 |
| `temporal.json` | 10 | 相对时间落地、事件过后过期、周期性安排和长期状态不应过期 |
| `dedup.json` | 6 | 重复和改写不应产生多条 |
| `multi_entity.json` | 6 | 多个人或物同时存在时，检索首位要对 |
| `paraphrase.json` | 10 | 查询和原文用词不同（坚果 → 花生、宠物 → 橘猫），以及整句提问 |

## 用例格式

```json
{
  "id": "correction-04",
  "desc": "习惯改变（不再）",
  "sessions": [
    {"date": "2026-03-04", "say": ["我每天要喝三杯咖啡"]},
    {"date": "2026-03-10", "say": ["我不再喝咖啡了，改喝茶"],
     "expect": {"remember": [["喝茶"]]},
     "queries": [{"q": "咖啡", "hit": ["喝茶"], "stale": ["三杯"]}]}
  ]
}
```

- 每个 session 是一天：用 `MEMORY_NOW` 把"现在"固定在该日期，逐句写入后跑一次 `consolidate --force`，然后检查。
  `say` 可以为空，用来模拟"几天后再看"，例如检查过期。
- 关键词匹配：一条记忆包含列表里的**全部**关键词才算匹配，英文不区分大小写。

| 断言 | 含义 |
|------|------|
| `expect.remember` | 活跃池里至少有一条记忆匹配 |
| `expect.forget` | 活跃池里没有任何记忆匹配 |
| `expect.unique` | 活跃池里最多一条记忆匹配 |
| `queries[].hit` | `search --json` 前 k 条（默认 3）中有匹配的 |
| `queries[].top1` | 第 1 条匹配 |
| `queries[].stale` | 前 k 条中没有"含过时关键词、又不含 `hit` 关键词"的结果 |

## 基线暴露的问题（已逐条确认根因）

按影响排序：

1. **更正后旧说法仍会被查到**：19 条只过了 3 条。相似度只看字面重叠，"我每天要喝三杯咖啡"和
   "我不再喝咖啡了"只共享"咖啡"，关联不上；隐式变化（分手、换手机）完全没有处理；被弱更正
   降权的旧记忆也没有从检索结果中排除。
2. **误合并导致丢记忆**：无更正词时重叠率 ≥0.6 就合并，"张三喜欢打篮球"和"李四喜欢打篮球"、
   "我对花生过敏"和"我对花粉过敏"、王老师 / 刘老师被合成一条，**第二条直接丢失**。
   丢一条过敏信息属于严重问题。
3. **5 个字的事实被丢弃**：`src/memory.py:3004` 的 Phase 1 只保留超过 5 个字的内容，然后清空
   pending，"我有高血压"、"我不吃香菜"就这样没了。`src/noise_filter.py:210` 还会把少于 5 个字的
   "我叫陈默"当作噪声。
4. **噪声规则误杀更正和事实**：`src/noise_filter.py:106-107` 把以"不对"、"哦"开头的句子当作
   闲聊，正好过滤掉"不对，我生日其实是5月13号"这类更正；`:125` 的 `写.*代码` 过滤掉了
   "我平时用 MacBook Pro 写代码……"。
5. **敏感信息照单全收**：密码、API Key、身份证号全部入库（0/3）。
6. **查询大小写敏感**：索引把英文转成小写，`keyword_search` 却不转换查询，所以搜 "iPhone"、
   "Python" 查不到。"项目B" 里的单个字母也没有进索引，导致项目 A / B 分不清。
7. **语义改写几乎查不到**：1/11。坚果 → 花生、宠物 → 橘猫、家乡 → 老家都查不到，需要语义检索。
8. **其他**：
   - 提问被当成事实存下来（"你觉得 Python 和 Rust 哪个好？"）
   - pending 模式下明天的复查预约因为重要性只有 0.2，在 Phase 2 被过滤
   - capture 和 pending 用的是两套不同的噪声过滤
   - capture 合并时保留旧内容，丢掉了更完整的新说法

## 维护约定

- **不要为了过评测改用例**。用例描述的是用户合理期望的行为；系统做不到就让它失败，在这里记录。
- 新增能力时先补用例，修改前后各跑一次，用 `--json` 对比。
- 已知暂时做不到的，例如语义改写，也保留在评测集里，作为路线图的度量。
