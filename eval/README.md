# 中文记忆评测集

84 个用例，按 Agent 实际看到的效果打分：回放多天对话后，**该记的记住了没有、不该记的有没有记、
查的时候能不能查到对的、会不会查到已经过时的**。

纯标准库，纯规则路径（运行时会去掉 `OPENAI_API_KEY`），结果可复现，一次约 15 秒。

```bash
python3 eval/run_eval.py                    # pending 模式：add-pending，每天结束 consolidate
python3 eval/run_eval.py --mode capture     # capture 模式：每句话都 capture（模拟 Agent 主动写入）
python3 eval/run_eval.py -v                 # 列出每条失败断言和当时的活跃记忆
python3 eval/run_eval.py --only correction  # 只跑某一类
python3 eval/run_eval.py --json out.json    # 保存逐条结果，便于前后对比
```

## 用例类别

| 文件 | 数量 | 测什么 |
|------|------|--------|
| `basic.json` | 12 | 身份、健康、偏好、关系等基础事实能否写入并查到 |
| `noise.json` | 11 | 寒暄、计算、翻译、提问等不该入库 |
| `privacy.json` | 3 | 密码、API Key、身份证号不该入库 |
| `correction.json` | 13 | 带更正词的修正（说错了 / 其实是 / 不再 / 换成 / 逗你的……），查询时不应再看到旧说法 |
| `preference_shift.json` | 5 | 没有更正词的隐式变化（改喝美式、分手、换手机） |
| `no_conflict.json` | 8 | **对照组**：相似但不冲突的事实不能被误合并或误失效 |
| `temporal.json` | 10 | 相对时间落地、事件过后过期、周期性安排和长期状态不应过期 |
| `dedup.json` | 6 | 重复和改写不应产生多条 |
| `multi_entity.json` | 6 | 多个人或物同时存在时，检索首位要对 |
| `paraphrase.json` | 10 | 查询和原文用词不同（坚果 → 花生、宠物 → 橘猫），以及整句提问 |

## 用例格式

```json
{
  "id": "correction-04",
  "desc": "习惯改变（不再）",
  "sessions": [
    {"date": "2026-03-04", "say": ["我每天要喝三杯咖啡"]},
    {"date": "2026-03-10", "say": ["我不再喝咖啡了，改喝茶"],
     "expect": {"remember": [["喝茶"]]},
     "queries": [{"q": "咖啡", "hit": ["喝茶"], "stale": ["三杯"]}]}
  ]
}
```

- 每个 session 是一天：用 `MEMORY_NOW` 把"现在"固定在该日期，逐句写入后跑一次 `consolidate --force`，然后检查。
  `say` 可以为空，用来模拟"几天后再看"，例如检查过期。
- 关键词匹配：一条记忆包含列表里的**全部**关键词才算匹配，英文不区分大小写。

| 断言 | 含义 |
|------|------|
| `expect.remember` | 活跃池里至少有一条记忆匹配 |
| `expect.forget` | 活跃池里没有任何记忆匹配 |
| `expect.unique` | 活跃池里最多一条记忆匹配 |
| `queries[].hit` | `search --json` 前 k 条（默认 3）中有匹配的 |
| `queries[].top1` | 第 1 条匹配 |
| `queries[].stale` | 前 k 条中没有"含过时关键词、又不含 `hit` 关键词"的结果 |

## 基线暴露的问题与处理

**已修复（第一轮）**

1. ✅ **误合并导致丢记忆**："张三 / 李四喜欢打篮球"、"花生 / 花粉过敏"被合成一条，第二条丢失。
   现在合并前先检查两句之间是否"换词"：只增删词才算同一件事，换了词就是不同事实
   （`MemoryOperator._is_substitution`）。合并时保留更完整的说法。
2. ✅ **5 个字的事实被丢弃**：Phase 1 不再按长度丢弃；噪声过滤的最短长度从 5 改为 3。
3. ✅ **噪声规则误杀**：以寒暄或应答开头的规则（"不对""哦""对""好的"……）只在句子里没有
   事实时才生效；`写.*代码` 改为只匹配"帮我写代码"这类请求；去掉"英文""中文"关键词。
   另外新增"不含事实的提问"过滤（"你觉得 Python 和 Rust 哪个好？"）。
4. ✅ **敏感信息入库**：新增 `contains_secret`，可识别密码、API Key / Token、身份证号、银行卡号；
   pending 和 capture 都会拒绝，capture 会提示原因。
5. ✅ **查询大小写敏感**：查询转为小写；"项目B"这类中文紧跟字母或数字的词也进入索引。
6. ✅ **pending 与 capture 不一致**：capture 现在先走和 pending 相同的噪声 / 敏感信息过滤。
7. ✅ **带日期的安排被筛掉**：有明确未来日期的内容，重要性至少 0.5，过期后自动归档。
8. ✅ **更正检测被实体拦截**："Java → Go"这类更正因两边实体不同被跳过，现在不再按实体过滤。
   "不对"加入弱更正词；被更正降权的旧说法不再出现在检索结果中，仍可用 `get` 取回。
9. ✅ 修复时发现：Phase 2 丢失了每句话的说出时间，pending 次日再整理时，"明天"会按整理当天
   换算成日期，现在会按原话的时间换算。

**第二轮：语义检索（可选）**

10. ✅ **语义检索**：新增 `src/embeddings.py`，支持 OpenAI 兼容接口或本地 ONNX 模型。关键词命中优先，
    语义结果补在后面。启用后语义改写 9/11。
11. ✅ **字面重叠少的更正**：带更正词时，若字面上找不到旧记忆，就用语义相似度（≥0.6）去找
    （"不再喝咖啡"→"每天三杯咖啡"）。

**仍未解决（需要 LLM 判断）**

- **没有更正词的变化**：如"我现在住在上海"→ 旧的"我住在北京海淀区"，以及分手、换手机、
  提前交完报告这类隐式变化（启用语义后仍有 9/19 失败）。
- **同义改写去重**："我养了一只橘猫叫年糕"和"我家年糕是只橘猫"仍是两条。
- **极短查询和跨语言**："坚果"→"花生过敏"、"peanut allergy"→"花生"，bge-small-zh 给出的
  相似度（0.24–0.25）和无关内容一样低。

前两类不能只靠 embedding：实测"花生过敏 / 花粉过敏"（0.86）、"张三 / 李四喜欢打篮球"（0.78）
与真正的同义改写（0.82–0.90）相似度一样高；无更正词的更正（0.60–0.79）和"相关但不冲突"
（0.57–0.59）也分不开。按相似度阈值合并或判定更正会重新引入丢数据的问题，需要 LLM 判断
"是同一件事 / 新的取代旧的 / 两件不同的事"（mem0 的做法），见 `docs/ROADMAP-agent-skill.md`。

## 维护约定

- **不要为了过评测改用例**。用例描述的是用户合理期望的行为；系统做不到就让它失败，在这里记录。
- 新增能力时先补用例，修改前后各跑一次，用 `--json` 对比。
- 已知暂时做不到的，例如语义改写，也保留在评测集里，作为路线图的度量。
