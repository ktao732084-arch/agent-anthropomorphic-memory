# 长期记忆端到端评测：Agent 能不能像人一样记住过去的对话

`eval/cases/` 测的是单条规则（会不会误合并、能不能识别更正）；这里测的是最终效果：
**几天甚至几个月的真实对话回放进记忆系统之后，Agent 回答"你还记得……吗"时答得对不对。**

## 流程

1. **回放**：按天把用户说的话逐句 `add-pending`，每天结束 `consolidate`（`MEMORY_NOW` 固定为当天）。
   默认只写入用户的话，与插件实际行为一致；`--ingest-assistant` 把 AI 的回复也写入。
2. **提问**：最后一天之后，Agent 只能看到 `search --json` 检索到的前 10 条记忆（带日期），据此回答；
   找不到就答"不记得"。
3. **判分**：LLM 对照标准答案判对错（措辞、日期格式不同不扣分）；"没说过"的题答"不记得"才算对。
4. **归因**（`diagnose.py`）：每道答错的题归到一个环节——没存进去 / 存了但没检索到 / 检索到但答错 / 编造。

对照组：

| 配置 | 含义 |
|---|---|
| `no_memory` | 不给任何记忆，下限 |
| `full_context` | 把全部原始对话直接给 LLM，相当于"完美记忆"，上限 |
| `rule` | 本系统，纯规则（默认配置） |
| `semantic` | + 语义检索（bge-small-zh-v1.5，本地） |
| `semantic_judge` | + 语义检索 + LLM 写入判断 |

## 数据集

| 数据集 | 语言 | 规模（抽样后） | 考察 |
|---|---|---|---|
| [MemoryBank](https://github.com/zhongwanjun/MemoryBank-SiliconFriend) | 中文 | 15 位用户 × 10 天，100 题 | 用户说过的事、某天发生了什么、**AI 自己推荐过什么** |
| [PerLTQA](https://github.com/Elvin-Yiming-Du/PerLTQA) | 中文 | 4 个人物，100 题 | 个人经历与对话细节 |
| [LoCoMo](https://github.com/snap-research/locomo) | 英文 | 2 段长对话（38 天），107 题 | 单跳 / 多跳 / 时间 / 推理 / 没提过 |
| 私有集（不公开） | 中文 | 作者本人 57 天真实对话，42 题 | 见下文 |

MemoryBank 原数据没有标准答案，由 LLM 根据完整对话生成一次（缓存），因此它的 `full_context` 分数偏乐观。

**私有集**：从作者本人的 OpenClaw / Claude Code / Codex 会话中提取用户原话（`extract_sessions.py`，
抽样规则见 `select_sessions.py`），由 LLM 分段抽取事实、按六类能力出题（单点事实、跨天整合、时间、
状态更新、偏好、没说过），再逐题对照完整记录核验，不合格的丢弃（`make_private_qa.py`）。
题目含个人信息，存放在作者的私有仓库，不随本仓库发布。

## 运行

```bash
bash eval/longterm/fetch_datasets.sh DATA_DIR
export OPENAI_API_KEY=... OPENAI_BASE_URL=https://api.deepseek.com
# 语义配置需要本地模型，见 src/embeddings.py
export MEMORY_EMBEDDING_PROVIDER=onnx MEMORY_EMBEDDING_MODEL_DIR=... \
       MEMORY_EMBEDDING_QUERY_PREFIX="为这个句子生成表示以用于检索相关文章："
python3 eval/longterm/run_longterm.py --data DATA_DIR --out results.json
python3 eval/longterm/diagnose.py results.json
```

答题、判分、出题用的模型默认 `deepseek-flash`（DeepSeek-V4.1-Flash），LLM 回复按请求内容缓存，重跑不重复计费。

## 结果（2026-10-28，DeepSeek-V4.1-Flash 答题与判分）

### 总体：离"像人一样记得"还差很远

| | 无记忆 | **完美记忆**（全文） | 纯规则 | + 语义检索 | + 语义 + LLM 判断 |
|---|---|---|---|---|---|
| 公开集（307 题） | 20 (7%) | **241 (79%)** | 102 (33%) | 101 (33%) | 101 (33%) |
| 私有集（42 题） | 8 (19%) | **38 (90%)** | 21 (50%) | 22 (52%) | 20 (48%) |

无记忆时答对的都是"没提过"类（答不记得即对）。合成用例上有效的语义检索和 LLM 判断，
在真实长对话上几乎没有提升——瓶颈不在它们解决的环节。

公开集分项（纯规则）：

| 数据集 | 类别 | 完美记忆 | 纯规则 |
|---|---|---|---|
| MemoryBank | 用户说过的事 | 37/40 | 23/40 |
| MemoryBank | 某天发生了什么 | 22/24 | 15/24 |
| MemoryBank | **AI 自己推荐/说过的** | 33/36 | **9/36** |
| PerLTQA | 对话细节 | 79/100 | 30/100 |
| LoCoMo（英文） | 单跳 / 多跳 / 时间 / 推理 | 63/83 | 13/83 |
| LoCoMo（英文） | 没提过（应答不知道） | 7/24 | 12/24 |

### 失败卡在哪（`diagnose.py`，纯规则配置）

| 数据集 | 没存进去 | 存了没检索到 | 检索到但答错 | 编造 |
|---|---|---|---|---|
| MemoryBank | 42 | 9 | 2 | 0 |
| PerLTQA | 56 | 3 | 11 | 0 |
| LoCoMo | 16 | 52 | 2 | 12 |
| 私有集 | 3 | 13 | 5 | 0 |

"没存进去"再细分（公开集 114 题）：**只出现在 AI 的回复里 64**、被归档 27、用户说了但被过滤 23。

### 发现的问题与验证过的改进

1. **只记用户的话，记不住 AI 说过的**：插件和收集器都只写入用户消息，"你推荐过我什么""你当时怎么说的"一律答不上。
   评测中把 AI 回复也写入（`--ingest-assistant`）：中文公开集 79 → **116/200**，MemoryBank 的"AI 说过的"9 → 28/36。
2. **衰减归档 = 硬遗忘**：分数衰减到 0.05 以下就移入归档池，归档池不参与检索。PerLTQA 对话跨度一两年，
   114 条记忆因此"消失"。评测中关掉衰减归档（`--archive-threshold 0`）：PerLTQA 40 → **56/100**。
   人会淡忘，但给了线索还能想起来——衰减应该影响排序，而不是让记忆再也找不到。
3. **已修复：过期归档会删掉经历过的事**。"今天（2023-04-28）我去公园散步"被当成到期的安排，第二天就归档。
   现在只有未来的安排才有到期时间，过期后只标记 `event_passed`，仍可检索。
4. **已修复：summary 类型让 consolidate 崩溃**（`KeyError: 'summarys'`），"总的来说……"这类日常说法会触发，
   且 Phase 1 已清空 pending，当天消息全部丢失。
5. **已修复：收集器丢掉几乎所有渠道消息**。真实 OpenClaw 会话中，旧版收集器取到 150 条，其中 147 条带着元数据外壳，
   干净的用户原话只有 3 条；修复后取到 458 条。
6. **检索被长消息霸占**：关键词检索按命中个数打分，没有 IDF 和长度归一化，几条上千字的长消息对什么查询都排在前面，
   含答案的短记忆（端口号、分支名）挤不进前 10。私有集 13/21 的失败是这个原因。LoCoMo（英文）另有 52 题检索未命中，原因未细分；本系统的分词和语义模型都以中文为主。
7. **只存原话，不提炼事实**：一条长消息原样成为一条记忆，既难检索也难判断更正。

在已修复 3 的版本上（中文公开集 79/200，40%），再加上 1、2 两项：116/200（58%）→ 132/200（66%）；
完美记忆是 171/200（86%），剩下的差距主要在 6、7。1、2 目前只是评测开关，还没有改成插件的默认行为。
