# 长期记忆端到端评测：Agent 能不能像人一样记住过去的对话

`eval/cases/` 测的是单条规则（会不会误合并、能不能识别更正）；这里测的是最终效果：
**几天甚至几个月的真实对话回放进记忆系统之后，Agent 回答"你还记得……吗"时答得对不对。**

## 流程

1. **回放**：按天把对话逐句 `add-pending --source <role>`，每天结束 `consolidate`（`MEMORY_NOW` 固定为当天）。
   当前默认写入用户和 AI 的回复，保留角色；`--user-only` 用于只写用户的消融实验，
   `--ingest-assistant` 作为显式开启的兼容选项保留。
2. **提问**：最后一天之后，Agent 只能看到 `search --json` 检索到的前 10 条记忆（带日期），据此回答；
   找不到就答"不记得"。
3. **判分**：LLM 对照标准答案判对错（措辞、日期格式不同不扣分）；"没说过"的题答"不记得"才算对。
4. **归因**（`diagnose.py`）：每道答错的题归到一个环节——没存进去 / 存了但没检索到 / 检索到但答错 / 编造。

对照组：

| 配置 | 含义 |
|---|---|
| `no_memory` | 不给任何记忆，下限 |
| `full_context` | 把全部原始对话直接给 LLM，相当于"完美记忆"，上限 |
| `rule` | 本系统，纯规则（默认配置） |
| `semantic` | + 语义检索（bge-small-zh-v1.5，本地） |
| `semantic_judge` | + 语义检索 + LLM 写入判断 |

## 数据集

| 数据集 | 语言 | 规模（抽样后） | 考察 |
|---|---|---|---|
| [MemoryBank](https://github.com/zhongwanjun/MemoryBank-SiliconFriend) | 中文 | 15 位用户 × 10 天，100 题 | 用户说过的事、某天发生了什么、**AI 自己推荐过什么** |
| [PerLTQA](https://github.com/Elvin-Yiming-Du/PerLTQA) | 中文 | 4 个人物，100 题 | 个人经历与对话细节 |
| [LoCoMo](https://github.com/snap-research/locomo) | 英文 | 2 段长对话（38 天），107 题 | 单跳 / 多跳 / 时间 / 推理 / 没提过 |
| 私有集（不公开） | 中文 | 作者本人 57 天真实对话，42 题 | 见下文 |

MemoryBank 原数据没有标准答案，由 LLM 根据完整对话生成一次（缓存），因此它的 `full_context` 分数偏乐观。

**私有集**：从作者本人的 OpenClaw / Claude Code / Codex 会话中提取用户原话（`extract_sessions.py`，
抽样规则见 `select_sessions.py`），由 LLM 分段抽取事实、按六类能力出题（单点事实、跨天整合、时间、
状态更新、偏好、没说过），再逐题对照完整记录核验，不合格的丢弃（`make_private_qa.py`）。
题目含个人信息，存放在作者的私有仓库，不随本仓库发布。

## 运行

```bash
bash eval/longterm/fetch_datasets.sh DATA_DIR
export OPENAI_API_KEY=... OPENAI_BASE_URL=https://api.deepseek.com
# 语义配置需要本地模型，见 src/embeddings.py
export MEMORY_EMBEDDING_PROVIDER=onnx MEMORY_EMBEDDING_MODEL_DIR=... \
       MEMORY_EMBEDDING_QUERY_PREFIX="为这个句子生成表示以用于检索相关文章："
python3 eval/longterm/run_longterm.py --data DATA_DIR --out results.json
python3 eval/longterm/diagnose.py results.json
```

答题、判分、出题用的模型默认 `deepseek-flash`（DeepSeek-V4.1-Flash），LLM 回复按请求内容缓存，重跑不重复计费。

## 当前实现与历史评测的边界（2026-10-29）

本轮已将“记录 AI 回复”和“衰减不硬归档”落到正式代码，并把默认关键词路径替换为 BM25。
AI 回复带 `source/role: assistant` 和 `AI 回复：` 前缀；它不能覆盖用户事实，
也不进入用户画像摘要、用户实体档案或作为证实用户推断的证据。

BM25 在活跃池和 pending 上使用同一份语料统计，参数 `k1=1.2`、`b=0.75`。
中文使用重叠二元字组；英文使用完整单词；数字和分支等标识符保留，并索引其组成部分。
重排采用 80% 归一化 BM25 相关性 + 10% 重要性 + 5% 最近访问 + 5% 衰减分数，
已有实体隔离仍可进一步降权。每次查询扫描当前语料，无需迁移旧关键词索引；大语料性能尚未实测。

旧的 `thresholds.archive` 不再引起衰减归档。`--archive-threshold 0` 兼容旧命令，
非零值会明确报错，避免实验参数被悄悄忽略。历史结果请用 `04b164e` 或相应旧提交复现。
历史归档不自动恢复；手动归档和已被更正的旧记录仍不进入默认检索。

**下方 33%、40%→58%→66% 等均是旧实现的历史评测，不能当作本轮 BM25 的成绩。**
离线验证见 [测试说明](../../tests/README.md)，长期重跑见下节。长消息的事实拆分仍未实现。

## 成对重跑结果（2026-10-29）

**公开集明显改善，私有集只有小幅、对判分敏感的改善。**
两版都重新答题：旧版是已修复事件过期问题的 `04b164e`，新版是三项改动合入后的 `3afd06c`。
均使用 `deepseek-flash`、temperature=0、检索前 10 条、纯规则写入；比较整包改动，没有逐项消融。

| 数据集 | 本轮旧版 | 本轮新版 | 变化（百分点） | 错→对 | 对→错 |
|---|---|---|---|---|---|
| memorybank | 49/100（49.0%） | 77/100（77.0%） | +28.0 | 31 | 3 |
| perltqa | 32/100（32.0%） | 62/100（62.0%） | +30.0 | 36 | 6 |
| locomo | 37/107（34.6%） | 52/107（48.6%） | +14.0 | 22 | 7 |
| 公开集合计 | 118/307（38.4%） | 191/307（62.2%） | +23.8 | 89 | 16 |
| 私有集 | 21/42（50.0%） | 23/42（54.8%） | +4.8 | 4 | 2 |

私有集首轮是 4 题由错变对、2 题由对变错。对两版全部 84 份既有回答统一复判（不重新答题）后，
旧版从 21/42 变为 22/42，新版仍为 23/42；因此净增为 **1–2 题**，不能认为个人记忆问题已解决。
私有输入沿用原固定样本，只有用户消息，没有 AI 回合，不能测量 AI 回复采集的收益。

### 改善集中在哪，哪些仍有问题

- MemoryBank 的“AI 曾说过什么”由 **8/36 → 29/36**；用户事实由 **26/40 → 33/40**；时间题仍为 15/24。
- PerLTQA 由 **32/100 → 62/100**。不再衰减归档与增加 AI 记录同时生效，本轮不拆分各自贡献。
- LoCoMo 的时间题 **4/24 → 15/24**、单点提取 **5/24 → 13/24**；但跨会话整合 **2/23 → 1/23**、
  推理 **3/12 → 1/12**，未提过的问题正确拒答 **23/24 → 22/24**。总分提升不代表各能力都提升。
- 私有集单点提取 **6/15 → 8/15**、状态更新 **0/3 → 1/3**；跨天整合仍是 **0/4**。
  仍需检验事实拆分、状态链和查询表达，而不是仅凭公开集涨分宣称已解决长期记忆。

### 评分修复与可比性

重跑时发现旧脚本只识别 ASCII 引号 `don't`，把 `I don’t remember` 的弯引号当成错误回答。
已用同一规则重新判定两版的全部拒答题，**没有重新生成回答**：旧版修正 11 题、新版修正 13 题。
修复前本轮公开分数是 107/307 和 178/307；修复后才是上表的 118/307 和 191/307。
修复只涉及拒答标点，不是记忆能力提升；净增由 71 题调整为 73 题。新增 3 项判分回归测试通过。

MemoryBank 的旧标准答案缓存未找回，本轮生成一次并冻结，旧版和新版共用同一份答案；
其余公开集使用源数据答案，私有集沿用原来的 42 道题及标准答案。
所以不能直接拿历史的 33% 与本轮 62.2% 相减。历史的全文对照、语义检索和 LLM 写入判断配置本轮未重跑。
首轮 LLM 自动判分仍有偏差，尤其私有集只有 42 题；没有宣称统计显著性。

初始生成上限沿用旧脚本（标准答案 2048、回答 1024、评分 512）；只对空答或截断进行统一扩额重试，
最多 8192，避免把服务输出失败计为记忆失败。具体次数记录在汇总 JSON，旧版和新版遵循同一策略。

### 复现与隐私

[机器可读汇总](../results/2026-10-29-longterm-summary.json) 记录来源提交、冻结公开输入的 SHA-256、
两版提交、分母、逐类别成绩、错→对/对→错和复判统计。全部 349 道题按同一问题键成对核对，
两版标准答案一致；总分等于分类成绩之和，净增等于错→对减去对→错。

回放为节省进程启动时间逐时间线隔离调用原 CLI 处理函数，并在每次调用前清空查询缓存。
用一条公开时间线的前两天、前两题，对照真实 subprocess CLI 验证了两版的活跃/归档记录和检索上下文完全一致；
这是一项抽样等价性检查，不是对每一条查询的形式证明。

复现时锁定汇总中的数据集提交，使用同一份冻结时间线：

```bash
# 旧版 checkout：04b164e（默认只写用户消息）
python eval/longterm/run_longterm.py --data DATA_DIR --sources "" --timelines FROZEN_TIMELINES.json --configs rule --out baseline.json
# 新版 checkout：3afd06c（默认写入双方）
python eval/longterm/run_longterm.py --data DATA_DIR --sources "" --timelines FROZEN_TIMELINES.json --configs rule --out improved.json
```

复核时两版均使用本次修复后的拒答判定；空答/截断应重试，而非计为错误。
公开冻结输入、完整回答和缓存留在评测工作目录；私有题目与逐题预测只写入私有仓库，
原始对话、检索上下文、私有缓存与密钥不进入公开仓库，也不把原始对话写回私有结果仓库。

## 历史结果（2026-10-28，DeepSeek-V4.1-Flash 答题与判分）

### 总体：离"像人一样记得"还差很远

| | 无记忆 | **完美记忆**（全文） | 纯规则 | + 语义检索 | + 语义 + LLM 判断 |
|---|---|---|---|---|---|
| 公开集（307 题） | 20 (7%) | **241 (79%)** | 102 (33%) | 101 (33%) | 101 (33%) |
| 私有集（42 题） | 8 (19%) | **38 (90%)** | 21 (50%) | 22 (52%) | 20 (48%) |

无记忆时答对的都是"没提过"类（答不记得即对）。合成用例上有效的语义检索和 LLM 判断，
在真实长对话上几乎没有提升——瓶颈不在它们解决的环节。

公开集分项（纯规则）：

| 数据集 | 类别 | 完美记忆 | 纯规则 |
|---|---|---|---|
| MemoryBank | 用户说过的事 | 37/40 | 23/40 |
| MemoryBank | 某天发生了什么 | 22/24 | 15/24 |
| MemoryBank | **AI 自己推荐/说过的** | 33/36 | **9/36** |
| PerLTQA | 对话细节 | 79/100 | 30/100 |
| LoCoMo（英文） | 单跳 / 多跳 / 时间 / 推理 | 63/83 | 13/83 |
| LoCoMo（英文） | 没提过（应答不知道） | 7/24 | 12/24 |

### 发现的问题与验证过的改进

1. **只记用户的话，记不住 AI 说过的**：插件和收集器都只写入用户消息，"你推荐过我什么""你当时怎么说的"一律答不上。
   评测中把 AI 回复也写入（`--ingest-assistant`）：中文公开集 79 → **116/200**，MemoryBank 的"AI 说过的"9 → 28/36。
2. **衰减归档 = 硬遗忘**：分数衰减到 0.05 以下就移入归档池，归档池不参与检索。PerLTQA 对话跨度一两年，
   114 条记忆因此"消失"。评测中关掉衰减归档（`--archive-threshold 0`）：PerLTQA 40 → **56/100**。
   人会淡忘，但给了线索还能想起来——衰减应该影响排序，而不是让记忆再也找不到。
3. **已修复：过期归档会删掉经历过的事**。"今天（2023-04-28）我去公园散步"被当成到期的安排，第二天就归档。
   现在只有未来的安排才有到期时间，过期后只标记 `event_passed`，仍可检索。
4. **已修复：summary 类型让 consolidate 崩溃**（`KeyError: 'summarys'`），"总的来说……"这类日常说法会触发，
   且 Phase 1 已清空 pending，当天消息全部丢失。
5. **已修复：收集器丢掉几乎所有渠道消息**。真实 OpenClaw 会话中，旧版收集器取到 150 条，其中 147 条带着元数据外壳，
   干净的用户原话只有 3 条；修复后取到 458 条。
6. **检索被长消息霸占**：关键词检索按命中个数打分，没有 IDF 和长度归一化，几条上千字的长消息对什么查询都排在前面，
   含答案的短记忆（端口号、分支名）挤不进前 10。私有集 13/21 的失败是这个原因。LoCoMo（英文）另有 52 题检索未命中，原因未细分；本系统的分词和语义模型都以中文为主。
7. **只存原话，不提炼事实**：一条长消息原样成为一条记忆，既难检索也难判断更正。

在已修复 3 的版本上（中文公开集 79/200，40%），再加上 1、2 两项：116/200（58%）→ 132/200（66%）；
完美记忆是 171/200（86%），剩下的差距主要在 6、7。在上述评测时，1、2 只是评测开关；
2026-10-29 已实现默认行为；本轮成对重跑结果见上方新章节。
